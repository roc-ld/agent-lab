# 一页确认单模板 —— 按板块出，甲方过目打勾（不签字冻结）

> ①xuqiu 拆完后**按板块**各出一份（一个板块一张单，别把全项目塞一张）。
> 用途：编排层甩在线文档链接（飞书/腾讯文档）给甲方，甲方**轻量过目**——只确认「拆解覆盖了我的需求、字段口径没理解错」，打个勾或写一句反馈即可。**不是签字冻结**：甲方后续按实际随时调整是常态，改动走 `change-log.md` 一行式变更记录，不走这张单。
> 判据：甲方能扫一眼就看懂「这个板块有哪几页、每页填什么、关键规则是什么」= 好单；要甲方翻蓝图 doc 才看得懂 = 没写到位。

## 怎么填

- **板块名**：对应一个业务域/一级导航（如：需求管理、库存管理、门店经营）。板块 = UI 索引里的一级 IA 节点。
- **页面清单**：该板块下的每一页（列表页/详情/录入/看板…）。页面来自 UI 权威索引，一页一行。
- **关键字段/字典**：每页**给甲方看得懂的字段名**（中文业务名，不是数据库列名），字典类字段列出**枚举值**（如状态：待处理/已发货/已完成）——甲方最容易在这里发现「你把我的字段理解错了」。字段来自 字段表 SSOT，翻成业务语言。
- **关键业务规则**：该页/该板块的**核心口径**（谁能操作、什么触发状态流转、数量怎么算、跟哪个板块联动）——这是甲方最该确认的东西，字段错了改一处，规则错了返一片。
- **甲方确认位**：甲方填。`☑ 覆盖` / `☐ 有问题` + 一句话反馈。**空着也无所谓**（轻量过目，不强制逐格勾），有反馈就写。

> stack-agnostic：下表占位符 `<板块名>` `<页面>` `<业务字段>` `<字典枚举>` `<业务规则>` 按项目实际替换。

## 出单后怎么走（衔接 §2 交付门 + 编排层）

1. xuqiu 每个板块出一份，落到 `doc/confirmation/<板块>.md`，登记进 `_manifest.json` 的 `artifacts.confirmation_sheets`（复数 map：`{"<板块>":{"path":"...","status":"pending|confirmed|revised"}}`，与 SKILL §0 manifest 一致）。
2. `_manifest.json` 置 `status=needs_human` + `needs_human.why="确认单待甲方过目"`——编排层据此把在线文档链接甩给甲方，**不是叫醒 负责人 拍板字段**（甲方口径的事甲方定）。
3. 甲方反馈回来 → 改蓝图/ticket + 追一行 `change-log.md`（日期 / 改了什么 / 波及哪些 ticket / 谁提的）→ 该板块单更新后重发。反复几轮直到甲方无异议。
4. **确认 ≠ 冻结**：甲方过目后仍可随时改，改动一律走 change-log；确认单只是「开工前对齐一次」，不是拦后续变更的闸。
