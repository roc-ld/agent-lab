# 新版补充（release 2026-09-22）

UI 行为使用第六种 form: E2E，见 [E2E 接缝](e2e-accept.md)。新版硬检每条 counterfeit、必要 E2E 与场景字段存在；仍不把关键词扫描当断言强度证明。下文五类非 UI 形态继续适用。

# accept 断言：按类形态指南（防弱断言批发）

> ⚠️ **`dag_lint` C5 是启发式提示，不是保证。** 红队实证：五种 form 的形态检查全部
> 可被绕过（注释里塞关键词就行——现已剥注释，但 `run: bash x.sh` 仍完全失明），
> 同时会误伤合法写法。所以 C5 的形态判定**一律 warning**，只有「run 为空」和
> 「DATA 里自造数据自证」是 error。
> **真正能区分强弱断言的只有变异测试**（见文末「冻结 gate 的变异测试」一节）——
> 静态 grep 永远做不到。本表是给**写断言的人**看的形态指南，不是机器闸门。

> 接缝文件。①xuqiu 写 accept 时按本表选 `form` 并满足强制形态；②zhixing 收敛时按 `form` 复核断言强度。
> 由来：一个 AI 批量产出几十份 accept，弱断言会系统性成批出现——`COUNT(*) BETWEEN a AND b > 0` 这种，菜单插错父级 / path 为空照样绿，而"菜单只改 parent 不改 path → 404""空 path 崩整个路由"都是真实事故。**只查 accept 存在性不够，必须查形态。**

## 强制形态表

| form | 场景 | ❌ 会被真实事故骗绿的弱断言 | ✅ 强制形态 |
|---|---|---|---|
| `DDL` | 建表/改字段 | 只 `DESC table` 有输出 | 必断 **6 公共字段全集**（create_by/create_time/update_by/update_time/create_dept/del_flag 或本项目等价集）都在 |
| `API` | 新增/改接口 | 只断 `code==200` | 必断 **返回行的内容**（字段齐全 / 关键值正确），不是仅状态码 |
| `MENU` | 菜单 seed | 只 `COUNT(*) 落号段 > 0` | 必断 **path 非空** + **getRouters/路由下发可达**（空 path、错父级要能被断出来） |
| `DATA` | 跨表/聚合口径 | 自造数据查回来自证 | 必断 **跨表对账**（库存三表平衡、聚合键粒度=展示行粒度）打在**实现方没写过的数据**上 |
| `STATE` | 状态机/流程 | 只断终态存在 | 必断 **非法转移被拒** + 关键路径全链转移可达 |

## 横切规则：反 mock / 反 stale（作用于 API / DATA form，防 D/E 类假绿）

form 表只保证「结构正确性」，拦不住 D 类（mock 兜底假绿）和 E 类（测旧 build stale）。对 API/DATA form 追加两条强制约束——它们不是第六个 form，是所有取后端数据的断言必须满足的前提：

- **反 mock（D 类）**：断言取的对象必须是**实现方没造过的白名单 seed 数据**（来自 reseed 确定性快照），且断言脚本**不得依赖任何 mock / devMock / 本地兜底数据源**。目的是证明数据真来自后端链路，而非前端兜底或自造自证。`dag_lint` 的 C5 据此判：run 里出现自造 `INSERT` / `mock` 关键字 → **error**（这一条没有合法反例，所以是唯一保持硬拦的形态项；其余形态检查都是 warning）。
- **反 stale（E 类）**：断言**跑之前先校验被测运行产物版本新鲜度**（后端 jar/commit、前端 build hash 对不上 → 直接 fail，不许在旧产物上断）。这条同时落进 `verify.sh` 的 §断言 0（必跑前置守卫），不是可选注释。

（这两类事故的事后兜底是 escape 台账 → 出现即把该 pattern 规则化进 L2 高危表；但 accept 层要有事前抓手，别全靠事后。）

## ★ 每条 accept 必须写一行「反例」（最省钱的一条规矩）

在 accept 里加一个字段，一句话：**把实现改成什么样，这条断言会红？**

```yaml
accept:
  - form: API
    run: bash verify/gen_start.sh
    counterfeit: "把 status 写成 done 但 preview_pngs 留空 —— 这条会红"
```

写不出 `counterfeit` 的断言就是装饰品，当场重写，**别让它进 ②zhixing**。

> **为什么这条比 QA 门更值钱**（2026-08 T006 的实测账）：那个项目 39 条 accept，
> 证伪时发现 **35 条「实现坏了它照样绿」**，其中 15 条背后是真 bug。这 35 条不是
> QA 不努力——它们从**写下来的那一刻**就是弱的。等到 ②zhixing 的 QA 门才发现，
> 代价是**整轮返工**；在这里发现，代价是**改一行 yaml**。
>
> D1 那个任务的 QA 门为此跑了 7 轮。**返工不是因为检得太严，是因为断言写得太松。**

## 八种见过的假绿形态（写 accept 时照着自查）

每一种都是真实发生过的——不是设想。写完一条 accept，对着这张表过一遍：

| # | 形态 | 一改就露馅的坏实现 | 怎么写才拦得住 |
|---|---|---|---|
| 1 | 「不许发生 X」只看**状态码** | 先落盘、再返回 400 | 断**副作用没发生**（文件没变 / 表没多行），不是断返回码 |
| 2 | **假两侧对账**：两边调同一个函数 / 同一份列表 / 同一个响应 | 那个函数整个返回错的，两边一起错，diff 恒为空 | 两侧的取数路径必须**真的不同源**（一侧读库、一侧读页面） |
| 3 | 只看文件**大小 / 后缀 / 自己盖的戳** | 自己画一张 2.3KB 的图冒充渲染产物 | 断内容特征（像素/页数/文本命中），别信自报 |
| 4 | 读到的是**上一次**跑剩下的文件 | 这次根本没产出，断言读的是旧的 | 跑之前先清产出目录，或断 mtime 晚于本次开始 |
| 5 | **恒真**：断的是写死的常量 / 拿字段跟它自己比 | 实现整个删掉也绿 | 断言里出现的每个值，问一句「它从哪来」 |
| 6 | 只堵**一个方向**（`susp < total`） | `susp = 0` 同样满足 | 上下界都写，或直接断等于期望值 |
| 7 | 走的是**错的那条路**（不存在的 id → 命中「查无此物」分支） | 真实路径从没被跑到 | 断言前先确认走到了要验的分支 |
| 8 | **验收数据不带病灶** | 判据再狠，样本里没病，判据就是摆设 | seed 里必须**故意埋**一条该被抓住的坏数据 |

第 2 和第 1 出现得最多（T006 里分别命中 6 次和 4 次）。**「两边一比，相等就对了」
是最容易写、也最容易恒真的形态**——写之前先问：这两边真的不同源吗？

## 冻结 gate 的变异测试（可选但推荐）

蓝图冻结、tickets 全部就绪后，抽 **20% 的 accept** 做一轮独立变异测试：往被测对象注入一个**已知类事故**（菜单删 path / 接口漏字段 / 对账故意不平），看断言会不会**仍然绿**。仍绿 = 该 accept 是弱断言，打回重写。这一步一个独立 agent 就能跑，成本低、收益是"回归包不建在沙上"。

## 与 ②zhixing 的衔接

- accept 是 testing-ai / verify.sh 的**结构化子集**（2-3 条最关键链路），不是全量测试。
- 每 ticket 的 accept **累积进回归包**（`regression/<域>/`），**每个任务的 QA 门**在确定性快照上全量重放——这是"以前好的没坏"的复利形态。
- accept **弱化**（删对账 SQL / 放宽阈值）单列为 wave audit 维度自动 diff；库存三表平衡类断言标 `protected`，改动必须走人决策。
