# fastapi-local-web 坑手册

> N=1，尚未蒸馏。以下全部来自动科院项目 2026-08-18 的本机实测，可复现。

## 1. DeepSeek 长输出会断（三次实测全中）

`IncompleteRead` / `invalid literal for int() with base 16`。表现为连接读到一半断掉。

| 场景 | 现象 |
|---|---|
| 41 张图一次批量打标 | 必挂 |
| 10 张一批 | 5 批里 2 批首次失败，重试 2 次仍丢 24% |
| 3 篇新闻稿提炼范式 | 读到 3,259 字节断开，重试第 2 次成功 |

→ 重试 ≥3 次 + 分批 5-8 + **非模型兜底**。三层缺一不可。

## 2. 模型会编造不存在的文件名

实测生成 PPT 时编了 `办公区域人员操作.jpg`。→ 凡是模型给的文件名/枚举值，
程序必须对着白名单校验，不合法就替换或打回，不能直接用。

## 3. 模型会走"删掉"这条捷径

deckkit 路线上实测 16% 的图片锚点被 `drop()` 掉，产出是空白色块而闸门看不见。
→ 校验器要专门检查"该填的位置是不是被删了"，这类静默降级比报错危险。

## 4. `.doc` 旧格式 python-docx 读不了

`soffice --headless --convert-to docx` 可转（实测 14 段/1043 字正常）。
产品要内置这一步，甲方手上一定有 `.doc`。
